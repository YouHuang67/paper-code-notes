# $post

在 `paper-code-notes` 里完成一篇论文的解读，并提交到可部署的网页。先读本文件，再读 `.codex/skills/doc/SKILL.md` 和 `.codex/skills/commit/SKILL.md`。长任务同时遵守 `.codex/skills/exec/SKILL.md`。不要用子代理，不要发问卷。

## 深度

按用户原话选择证据来源档位，不要自行扩大到代码分析。无论选择哪档，论文报告都必须完整、详细；“默认只解读论文”限定资料来源，正文仍需展开方法、公式、实验和证据边界。

- 默认：基于论文正文与附录完整解读论文已有内容。还原论证，中文写清楚，专名保留英文，补足理解方法所需背景。逐步解释方法、公式、实验和结论；不克隆代码，不推测未报告的算子实现。
- 用户写了「必须基于其提供的开源代码深入解析」：在默认之外，克隆官方仓库，对照论文核对模块、训练或推理入口、关键数据流。权重和数据不入库。
- 用户写了「必须深入解析其开源代码的算子设计以及其他所有具体实现部分」：在上一档之外，写清算子的张量形状、算法阶段和与论文公式的对应。仓库未开源或没有该算子时，写明缺了什么，不要编造实现。

## 顺序

1. 定位论文。日报里的短名先查 `refs/scans/daily/index.md`，再打开对应日期文件拿编号。PDF 放 `refs/papers/`，不提交。
2. 先通读论文正文和与方法、实验相关的附录，记录章节、图表、公式、实验配置与结论的对应关系。不能只凭 abstract、日报摘要或旧笔记改写报告。
3. 笔记写到 `docs/paper_reading/<短名>.md`。开头是论文链接、代码链接、团队，然后是「概述」。正文按论文论证顺序展开，满足下方的报告完整性要求。末尾写可迁移的设计点。
4. 同步 `mkdocs.yml` 的 nav 和 `docs/data/tag_index.json`。索引里要有 `category` 和 `tags`。未选分类时出现在全部列表。`category` 用已有分类名。
5. 代码档仅在深度要求写到代码时才写，放 `docs/code_analysis/<项目>/`。克隆的仓库、权重、`refs/` 不提交。
6. 按 `$doc` 做逻辑连续性和读者经济性两轮审阅，再逐项核对下方完整性清单。缺少论文关键内容时先补齐，不能以精炼为由略过。完成构建和差异检查。
7. 提交报告、`mkdocs.yml`、`docs/data/tag_index.json` 中本次实际改动的文件；新报告须核对 HEAD 中三处均已登记。说明用简短英文，不要 `Co-authored-by`。
8. 执行 `git push origin main`。网页由 `.github/workflows/deploy.yml` 在 `main` 被推送后构建。不要手推 `gh-pages`。推送后用 `git status -sb` 确认没有领先 `origin/main`。
9. 回复笔记路径、来源档位、提交号，以及页面地址 `https://YouHuang67.github.io/paper-code-notes/paper_reading/<短名>/`。Actions 未成功时写明还没构建完，不要说已经能看到。

日报页面与论文页面分开维护。`refs/scans/` 内容不写进 `docs/`。

## 报告完整性

报告是可独立阅读的技术解读，篇幅由论文的方法和证据复杂度决定，不设字数目标；每个关键问题都要解释到读者无需回看原文即可理解论文主张、实现路径和证据边界。

1. **背景与问题**：说明任务、已有方法、具体失效现象，以及论文要解决的技术问题。区分作者观察、作者假设与已经验证的事实。
2. **方法主链**：按输入、处理步骤、训练或推理目标、输出的因果顺序讲清每个关键模块。解释为何需要这一步、它如何影响下一步，并说明相对基线改变了什么。不能只列模块名或一句话概括机制。
3. **公式与实现条件**：保留决定方法行为的公式，定义符号、目标、掩码、阈值和归一化方式，解释公式如何落到算法步骤。写清论文给出的模型、数据构造、采样策略、训练配置和推理设置；未报告的细节明确标注，不能自行补造。
4. **实验与证据**：交代基线、数据集规模、评测指标及其计算口径、主要数值结果、消融和失败案例。把结论与对应表图或实验条件连起来；比较时注明绝对值、相对增益和适用范围，避免只写“显著提升”。
5. **分析与边界**：解释作者如何从实验支持机制判断，指出替代解释、未验证场景和复现所依赖的关键条件。区分论文结论与笔记者的推论；迁移设计点应有明确依据，不写成未经验证的效果承诺。

若论文某一项确实没有提供数据或细节，直接说明缺失及其影响。方法、核心实验和关键消融需要展开到足够支撑判断的程度；报告末尾可有简短总结，正文分析仍需完整保留。

## 文风

概述能单独读完，正文展开证据与推导，避免用概述替代解释。清晰优先于短；删除重复和空话，保留必要细节、数值与条件。表格只用于实验对比。正文采用普通段落和标题。中文句子里保留 WanPE、GRPO 这类专名。句首用可指代的短名。
