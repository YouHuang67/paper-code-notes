# 论文日报规范

## 目标

日报负责在单日范围内提供可检索的论文摘要。论文深度解读由 `docs/paper_reading/` 独立承载。日报条目保持统一的信息角色：研究问题、方法、实验范围、判断和标签。

## 标签数据契约

每个日报条目使用四个相互独立的字段：

```html
<article class="daily-paper-card"
  data-topic="主题"
  data-org="论文单位"
  data-coverage="覆盖面"
  data-task="任务类型">
```

- `topic`：对应 `scripts/paper-daily.json` 中启用的主题名。
- `org`：按论文首页作者单位标记为 `大公司参与`、`产业研究机构` 或 `高校/研究机构`。
- `coverage`：按方法作用范围和实验任务覆盖标记为 `跨任务通用`、`任务内通用` 或 `细分任务`。`跨任务通用`表示方法已在不同任务类型中验证或直接作用于共享训练机制；`任务内通用`表示方法覆盖同一任务下的多个模型、数据集或设置；`细分任务`表示证据集中于单一任务变体或特定数据条件。
- `task`：描述论文直接处理的任务对象，例如 `视频生成`、`语言模型`、`音频语言模型`、`工具调用`。

筛选器在同一维度内使用 OR 逻辑，维度之间使用 AND 逻辑。每个维度的“全部”表示取消该维度限制。标签用于定位，判断仍以条目正文和论文证据为准。

每个选项旁显示当前日报匹配数量。该维度处于未筛选状态时，数量结合其他维度的已选条件，表示选择该选项后的可用论文数；该维度已有筛选条件时，数量只反映当前结果集，已选项显示实际数量，其他选项显示 `0`。用户调整任一维度后，所有数量立即刷新。

## 条目内容

每篇条目按固定顺序写成：

1. 论文标题和可访问的论文链接；
2. `标签` 行，标签与四个 `data-*` 字段保持一致；
3. `问题`：说明论文试图解决的对象和失效现象；
4. `方法`：保留决定方法行为的核心机制和必要公式；
5. `实验范围`：给出数据、任务、基线和关键结果覆盖；
6. `判断`：说明证据支持的适用范围和局限。

日报不写论文深度解读链接、不加入与方法无关的机构评论，也不使用“信息缺失”等流程性话术填充条目。

筛选结果为空时，相关任务分区标题同步隐藏，页面只保留有匹配条目的分区。日报总览文本保持固定的篇数与任务覆盖描述，不在概览中重复覆盖面标签定义。

## 推送契约

日报网页和微信消息承担不同的信息密度：

- 网页保存当天完整条目、四维标签、实时筛选和论文链接。
- 微信消息保留日期、主题分组和每篇的一句摘要，并在消息末尾增加当天日报网页地址。
- 网页地址是新增入口，微信摘要继续发送；后续自动推送使用固定顺序：日期 → `[论文]` 摘要 → `日报网页：` 地址。
- 微信正文中的结论采用“【主题】”和“— 名称：一句结论”格式，网页条目沿用结构化的 `问题`、`方法`、`实验范围`、`判断`。

## 自动化约束

生成或更新日报后运行：

```bash
python3 scripts/validate_daily.py
```

校验器检查每个条目是否包含四个维度、标签字段是否完整，以及页面是否保留统一的内容段落。部署流程应在 MkDocs 构建前执行校验，防止标签结构漂移。
