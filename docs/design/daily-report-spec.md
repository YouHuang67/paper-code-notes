# 论文日报规范

## 目标

日报页面按日期归档，每篇论文独立成条目，给出完整论文信息和结构化解读。筛选维度只保留主题、作者单位类型和研究层级。页面不建立具体任务分类或任务筛选项。

## 页面标签契约

每篇论文卡片包含三个字段：

```html
<article class="daily-paper-card"
  data-topic="主题"
  data-org="机构类型组合"
  data-level="通用或垂类">
```

- `topic` 对应 `scripts/paper-daily.json` 中启用的主题。
- `org` 汇总作者单位的机构类型：`高校`、`企业`、`科研机构`、`个人`、`其他`、`待核实`。共同署名按固定顺序组合，例如 `高校+企业`。筛选器按组合中的单个类型匹配。
- `level` 只有 `通用` 和 `垂类`。论文的方法在多个不同领域得到验证，或直接作用于跨领域训练机制时标记为通用；方法适用范围集中于一个领域时标记为垂类。
- 具体任务名称保留在问题、方法和实验范围正文中，不作为页面标签或筛选维度。

每篇条目显示原样作者单位和逐单位分类，两个字段按原顺序一一对应。论文没有列出作者单位时使用“论文首页未列出作者单位”，机构类型为“单位未列出”。作者单位只从论文题名、作者及摘要开始处的署名区提取；城市、州和国家等独立地址片段不作为作者单位。机构分类证据只采用论文列出的作者单位。

机构类型规则位于 `scripts/daily-institution-types.json`。高校名称、企业法定后缀和已维护别名由本地规则识别；DeepSeek 为每个单位返回类型，独立复核其归类。名称线索和模型判断冲突时拒绝该分析结果；缺少可靠依据时标记“待核实”。结构校验器也会复核清晰名称线索并排除独立地址片段。ROR 官方词表定义 `education`、`company` 等机构类型，可作为类型语义参考；当前流程不依赖在线 ROR 请求，运行时使用本地规则和模型分类。规则覆盖不到的新机构需在核验后加入别名表。 FNii-Shenzhen 官网注明依托香港中文大学（深圳）建设，省未来智联网络重点实验室也列于该大学科研平台页；两项按高校依托研究单元归为高校。官方来源、分类依据和完整署名别名保存在机构类型配置的 `evidence` 中。

机构类型说明署名单位性质，不说明算力、数据规模或资源支持。资源信息仅在论文实验设置、致谢或正文明确披露时写入实验范围或判断。

同一筛选维度的多选按 OR 计算，主题、机构类型和层级之间按 AND 计算。未选择的维度显示结合其他条件后的可用篇数；已选择的维度显示当前结果集的篇数。筛选结果为空时显示零篇匹配。

## 条目内容

每篇论文按以下顺序展示：

1. 完整标题、arXiv 摘要页链接和论文 PDF 链接；
2. 主题、机构类型和研究层级标签；
3. 作者、公告日期、公告更新类型、阅读版本、作者单位及单位分类；
4. `问题`：研究对象和论文所针对的局限；
5. `方法`：核心机制、训练设置和必要公式；
6. `实验范围`：数据、模型、基线和关键结果；
7. `判断`：证据所支持的适用范围和局限；
8. 原文摘要和可核验的正文引句。

每篇论文使用独立卡片，卡片按日报入选顺序平铺。主题以标签和筛选项展示，不形成论文分组标题；任务只保留通用、垂类两个层级。日报不放独立深度笔记链接，不加入与论文方法无关的机构评论。

## 微信推送

微信正文承担简讯作用，完整论文解读保存在当天网页中。消息包含日期、主题分组、最多八条摘要以及已经部署的日报网页链接。链接标题“日报网页”单独成段，下一段只放完整裸 URL。发送前按 [微信链接交付 SOP](wechat-link-delivery-sop.md) 检查最终正文。

## DS 处理契约

1. DeepSeek 按主题边界审核完整候选摘要，返回论文 ID、接收决定、主题、证据引句和排除条件检查；独立复核再次确认主题与证据。
2. 入选论文按公告版本下载 PDF，抽取正文并分段整理证据。DeepSeek 输出问题、方法、实验范围、判断、短摘要、通用/垂类层级、作者单位和逐单位机构类型。
3. 作者单位必须逐字出现在论文题名页作者署名区。机构类型必须与单位逐条对应，并通过名称规则、独立复核和结构校验。类型依据不足时标记“待核实”；机构规模字段不参与高校或企业性质判断。
4. 独立审查确认研究对象、方法、数字、单位类型、层级和短摘要。存在事实错误时依据论文正文逐项修正；全部入选论文通过审核后才生成日报。
5. 每篇审查结果以论文 ID 写入 `analyses/<id>.json` 检查点。页面生成器按 ID 读取检查点，移除旧 `task` 字段，并把旧三档覆盖标签迁移为两档层级；当前结果只使用新契约。并发分析完成顺序不参与字段配对。
6. 已送达的早期运行缺少逐篇检查点时，`repair` 只接受完整且与状态 ID 顺序一致的报告行；每篇原始 PDF、正文抽取、作者单位和证据引句均须通过校验。该修复来源记录于 `artifact_verification`，用于页面恢复并保留原始送达状态和发送次数。部分检查点或缺失来源会阻止回退。

## 自动校验

生成或更新日报后运行：

```bash
python3 scripts/validate_daily.py
```

校验器核对三类卡片属性、机构组合、逐单位分类与作者单位数量、标签一致性、层级枚举、文章闭合和正文必需段落，并拒绝旧任务、覆盖面筛选字段和明确地址误标。存在本地批准运行资料时，校验器还会核对报告、检查点、PDF 作者署名区、页面字段和内容指纹。部署流程在 MkDocs 构建前执行校验。

## 发布与交付门禁

日报流程由 `scripts/daily_pipeline.py` 管理，状态保存在 `refs/scans/daily-runs/YYYY-MM-DD/`。已准备的报告先发布到公开网页；网页响应必须包含当前内容指纹，之后才调用微信桥接。仅当该 `run_id` 有 `ok=true` 回执时记入去重账本并标记 `delivered`。来源、模型、部署或微信回执未就绪时保留可恢复状态，不发送空日报。完整运行命令、状态恢复和调度关系见 [日报交付流程](daily-delivery-pipeline.md)。
