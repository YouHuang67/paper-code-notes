# 论文日报规范

## 目标

日报负责在单日范围内提供可检索的全文解读。独立专题笔记由 `docs/paper_reading/` 承载。日报条目保持统一的信息角色：研究问题、方法、实验范围、判断和标签。

## 标签数据契约

每个日报条目使用四个相互独立的字段：

```html
<article class="daily-paper-card"
  data-topic="主题"
  data-org="机构组合"
  data-coverage="覆盖面"
  data-task="任务类型">
```

- `topic`：对应 `scripts/paper-daily.json` 中启用的主题名。
- `org`：按论文首页或正文列出的作者单位，归类为 `大型机构独占`、`大型机构+高校/非大型机构`、`高校/非大型机构独占`、`单位未列出` 或 `单位层级待核实`。`大型机构独占`表示署名单位全部属于大型企业或大型研究机构；`大型机构+高校/非大型机构`表示至少一个大型企业或大型研究机构与高校或其他非大型单位共同署名；`高校/非大型机构独占`表示署名单位中没有可确认的大型企业或大型研究机构。企业和产业研究机构统一纳入产业机构层级判断。
- 机构层级采用 `scripts/daily-institution-scale.json` 中逐个维护的名单。机构不在名单中时标记为 `单位层级待核实`，页面仍可发布；该状态明确提示后续人工核实，不能把未知项默认归为小机构。
- 每个条目必须显示 `作者单位` 行，原样保留论文列出的单位名称。论文未列出作者单位时，显示“论文首页未列出作者单位”，不得根据作者姓名、版权标记、项目页或外部知识推断机构类别；此类条目标记为 `单位未列出`，不进入前三类机构组合筛选。
- 机构组合只描述署名结构，不等同于算力、数据规模或项目资源证明。算力支持只有在论文实验设置、致谢或正文明确披露时才写入实验范围或判断。
- 论文明确报告硬件、算力项目或资源支持时，在 `实验范围` 中记录原文可核验的信息；没有明确披露时不从机构组合推断资源条件。
- `coverage`：按方法作用范围和实验任务覆盖标记为 `跨任务通用`、`任务内通用` 或 `细分任务`。`跨任务通用`表示方法已在不同任务类型中验证或直接作用于共享训练机制；`任务内通用`表示方法覆盖同一任务下的多个模型、数据集或设置；`细分任务`表示证据集中于单一任务变体或特定数据条件。
- `task`：描述论文直接处理的任务对象，例如 `视频生成`、`语言模型`、`音频语言模型`、`工具调用`。

筛选器在同一维度内使用 OR 逻辑，维度之间使用 AND 逻辑。每个维度的“全部”表示取消该维度限制。标签用于定位，判断仍以条目正文和论文证据为准。

每个选项旁显示当前日报匹配数量。该维度处于未筛选状态时，数量结合其他维度的已选条件，表示选择该选项后的可用论文数；该维度已有筛选条件时，数量只反映当前结果集，已选项显示实际数量，其他选项显示 `0`。用户调整任一维度后，所有数量立即刷新。

## 条目内容

每篇条目按固定顺序写成：

1. 论文标题和可访问的论文链接；
2. `标签` 行，标签与四个 `data-*` 字段保持一致；
3. `问题`：说明论文试图解决的对象和失效现象；
4. `方法`：保留决定方法行为的核心机制和必要公式；
5. `实验范围`：给出数据、任务、基线和关键结果覆盖；
6. `判断`：说明证据支持的适用范围和局限。

日报不写论文深度解读链接、不加入与方法无关的机构评论，也不使用“信息缺失”等流程性话术填充条目；单位证据仅作为可核验的作者署名信息展示。

筛选结果为空时，相关任务分区标题同步隐藏，页面只保留有匹配条目的分区。日报总览文本保持固定的篇数与任务覆盖描述，不在概览中重复覆盖面标签定义。

## 推送契约

日报网页和微信消息承担不同的信息密度：

- 网页保存当天完整条目、四维标签、实时筛选和论文链接。
- 微信消息保留日期、主题分组和最多八篇的一句摘要，摘要之后必须附上当天已经发布的日报网页地址。
- 含网页地址的推送使用固定顺序：日期 → 主题摘要 → 单独一行的“日报网页”标题 → 下一段独占一行的裸 URL。裸 URL 必须从行首开始，不加项目符号、编号、括号、Markdown 包装、前缀标签或行尾标点，以保证微信识别为可点击链接。
- `scripts/daily_pipeline.py` 统一生成摘要和网页地址，网页地址使用裸 URL。
- 微信正文中的结论采用“【主题】”和“— 名称：一句结论”格式，网页条目沿用结构化的 `问题`、`方法`、`实验范围`、`判断`。
- 微信链接发送和发布前检查统一遵守 [`wechat-link-delivery-sop.md`](wechat-link-delivery-sop.md)。

## 自动化约束

生成或更新日报后运行：

```bash
python3 scripts/validate_daily.py
```

校验器检查每个条目是否包含四个维度、标签字段是否完整，以及页面是否保留统一的内容段落。部署流程应在 MkDocs 构建前执行校验，防止标签结构漂移。

## 每日交付状态机

日报使用 `scripts/daily_pipeline.py`，状态目录为 `refs/scans/daily-runs/YYYY-MM-DD/`。状态只允许沿以下路径推进：

`waiting_announcement → prepared → publishing → published → delivered`

其中 `pending`、`failed` 是待重试状态；`skip_no_announcement`、`already_processed` 和 `no_matches` 是当天终态。任何状态都不能直接生成“今天没有”消息。

### 时间与来源

arXiv 官方公告按美国东部时间发布，周日到周四有公告，周五和周六没有常规公告。脚本在北京时间早间窗口每 5 分钟运行一次，公告日期与页面标题必须一致；来源未就绪时保留 `pending`，下一轮重试。抓取使用官方 `/list/cs/new`，robots、响应摘要、哈希和候选元数据写入运行目录。

### DS 处理契约

1. 候选按 12 篇分批提交，完整摘要、作者和分类一起输入；每篇必须返回结构化接受/拒收、主题、证据引句和排除条件判断。
2. 入选项再次独立复核；主题对象不一致或证据引句不在摘要中时丢弃。模型不提供可审计的置信度字段，流程以结构化理由、排除条件和独立复核作为门禁。
3. 入选论文顺序确定后，顺序下载 v1 PDF 并用 `pdftotext` 提取正文。DeepSeek 按正文分段提取证据，再生成问题、方法、实验范围、判断、覆盖面、任务和作者单位；每个事实必须带正文引句。
4. 生成网页前再次审查对象、方法、数字、机构和覆盖面。任一校验失败，状态为 `failed`，禁止发布。
5. 所有请求、响应、解析结果、失败原因和提示版本保存在运行目录；重复运行优先复用成功缓存。

### 发布与微信门禁

`publish` 使用专属 worktree，只写当天日报、日报索引和导航，运行校验与 MkDocs 构建后提交并推送 `main`。`deliver` 读取公开 URL，必须确认 HTTP 成功响应包含本次内容指纹，随后发送精简消息。消息最多 8 条摘要，URL 独占一行；微信桥接日志必须出现本次 `run_id` 的 `ok=true`，之后才写入去重账本。公众号或网页部署延迟时保持 `publishing`，下一轮重试。

### 调度命令

```text
scripts/paper_daily.py install
scripts/daily_pipeline.py tick
scripts/daily_pipeline.py status --day YYYY-MM-DD
```

`daily_job.sh` 只启动独立的 `exec-paper-daily` tmux 会话；Python 文件锁保证抓取、发布和发送不并发。周末、官方节假日或确实无公告时保留状态记录，不向微信发送空日报。9:30 是检查和发送门槛，外部来源、模型和部署耗时可能导致延迟；流程记录实际时间，不伪造准点成功。
