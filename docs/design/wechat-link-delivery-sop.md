# 微信链接交付 SOP

## 目的

确保从网页、论文笔记或日报复制到微信的链接可被客户端识别并直接点击。微信消息按纯文本交付时，链接必须使用独立段落中的裸 URL。

## 输出格式

链接所在行必须满足以下约束：

1. URL 从该行第一个字符开始；链接前不加项目符号、编号、括号、引号、Markdown 链接语法、反引号或“链接：”等标签。
2. 一行只放一个完整 URL。URL 前后均换行，使其成为独立段落。
3. URL 行末不加句号、逗号、右括号等标点，也不在同一行附加说明。
4. 多个链接时，每个 URL 各占一行。需要说明链接名称时，将名称放在 URL 的上一行。
5. 使用完整的 `https://` 地址，不用短链、相对路径或省略协议的域名。

正确格式：

```text
BVB 论文解读
https://YouHuang67.github.io/paper-code-notes/paper_reading/bvb/
```

错误格式包括：

```text
- https://example.com/page/
网页链接：https://example.com/page/
[查看网页](https://example.com/page/)
（https://example.com/page/）
https://example.com/page/。
```

## 推送流程

1. 从仓库规范或构建配置生成最终绝对 URL，不手工猜测路径。
2. 检查 URL 对应的网页已经部署；论文页、日报页分别核对其实际路由。部署状态未知时，不把“已推送”表述成“已上线”。
3. 组装消息时先放简短说明，再把每个链接按上述格式放在独立段落中。不能让 Markdown 列表或行首符号包住 URL。
4. 发送前检查最终消息正文，而不只检查草稿或 Markdown 源文件：搜索每个 `https://`，确认它位于行首、单独成行且行尾没有标点或其他文字。
5. 有条件时，从微信端实际点击验证目标路由；否则至少验证部署状态与 URL HTTP 响应，并明确区分“HTTP 可访问”和“微信端已实测可点击”。


## 日报与论文解读

- 日报消息末尾可单独放一行“日报网页”，下一段单独放完整 URL；不得把“日报网页：”与 URL 写在同一行。
- 论文解读的每个页面链接采用“论文短名”一行、裸 URL 下一行的格式；多个页面逐组重复。
- 网页内的 Markdown 超链接不受本 SOP 的纯文本格式约束；本 SOP 约束的是发送给微信的消息正文。

## 发布前检查清单

- [ ] 页面已部署，路径与仓库导航一致。
- [ ] 每个 URL 使用完整 `https://` 地址。
- [ ] URL 从行首开始，无项目符号、序号、括号、标签或 Markdown 包装。
- [ ] 每个 URL 独占一行，前后有换行，行尾没有标点。
- [ ] 检查的是最终发送正文；未把网页内 Markdown 链接误当作微信正文链接。
- [ ] 对可访问状态和微信点击状态分别陈述，不互相替代。
