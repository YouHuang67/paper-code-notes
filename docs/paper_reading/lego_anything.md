# LEGO-Anything：通过编码 Agent 从单图重建可执行三维场景

- 论文：[arXiv:2609.36380](https://arxiv.org/abs/2609.36380)（2026-09）
- 项目：[LEGO-Anything](https://lego-anything.com)
- 作者单位：University of Maryland, College Park、Amazon Web Services；论文注明第一作者研究工作在 AWS 实习期间完成。

## 概述

LEGO-Anything 将单张 RGB 图像重建为可编辑、可执行、可查询的 Blender 场景程序。通用 coding agent 反复编写并执行 Blender 代码，渲染中间结果，与输入图像比较后继续修订。论文同时提出 LEGO-Bench 评估重建质量，分析迭代过程中的错误，并以 LEGO-Plugin 改善 agent 工作流；LEGO-World 则检验重建场景能否支持检测、分割和深度读取。

## LEGO-Bench 与指标

LEGO-Bench 含 104 个室内外模拟场景、208 张渲染图像。每个场景保留完整三维真值、深度和实例掩码，因而可以自动评价场景重建。评测拆分为三类：工件有效性（场景是否成功生成并可用）、可见表面几何重建、渲染外观。拆分指标能区分交付失败、几何布局偏差和材质光照差异。

几何指标先按对象计算精确率与召回率，再求对象级 F1 的平均：

\[
F_{i,o}=\frac{2P_{i,o}R_{i,o}}{P_{i,o}+R_{i,o}},\qquad
R_i=\frac{1}{|O_i|}\sum_{o\in O_i}F_{i,o}.
\]

点到点匹配容差随参考点深度变化，设为前向深度的 5%；参考表面和重建表面均投影至图像平面，在对象掩码内对比，计算时保持相机坐标，不做尺度对齐。外观指标由评测器统一重渲染场景，统计 RGB 各通道最大误差不超过 30/255 的像素比例。单个有效案例分数为 \((R_i+A_i)/2\)，无效工件计零；总分对全部尝试案例取平均：

\[
S=\frac{1}{N}\sum_{i=1}^{N}\frac{1}{2}(R_i+A_i)V_i.
\]

摘要报告表现最强的 GPT-6-astra 在室内得分为 53.4%，室外为 39.6%。有效产出场景与准确恢复几何、外观之间仍有明显差距。论文指出，室外场景得分更低，显示复杂布局与开放环境给单图场景恢复带来更高难度。具体分项评价依赖基准内模拟场景与相机设置，不能直接视为真实世界重建精度的完整估计。

## Agent 迭代与 LEGO-Plugin

轨迹分析识别出三种问题：初始场景建立较弱、后续编辑损害已有正确部分、自我评估依据不足。以 GPT-5.6-sol 为例，29.6% 的编辑导致分数下降，最终结果比其轨迹中最佳中间场景低 3.2 分；GPT-6-astra 则更早得到首个可评价场景，留出更多预算用于改进。

LEGO-Plugin 作为训练无关的 harness 扩展，围绕上述问题包含三个组件：Enhanced Initialization 用输入图像提供更可靠的起始场景；Grounded Refinement 以图像证据支撑修改判断；Version Control 保存有效版本，避免回归编辑覆盖较好结果。作者在 Office 子集的六个模型上测试，所有模型均有提升，最高相对增益为 62.7%。相对增益受基线分数影响，解读时应同时查看绝对分数和子集范围。

## LEGO-World 与结果解释

LEGO-World 将重建场景作为显式表示，通过确定性查询导出物体检测、实例分割和相对深度。GPT-6-astra 重建场景在三项任务上均呈现非零能力，但整体落后于针对相应任务训练的专用视觉模型。此实验检验的是场景程序能否作为结构化视觉表征，结果表明当前重建精度尚不足以取代专用感知系统。

## 分析与边界

论文的重要方法学贡献是把最终重建与中间轨迹同时纳入分析。若只看最终提交，初始化慢和编辑回归会被压缩为一个总分；轨迹指标使系统级改进目标变得可定位。LEGO-Bench 的精确几何真值来自模拟器，评测具备可控性，但图像分布、资产库和渲染风格会影响向自然拍摄图像的外推。插件增益在指定 Office 子集和所测模型中成立，迁移到其他 agent harness 仍需验证。

## 基准构造与完整指标链

LEGO-Bench 的 104 个逻辑场景来自 8 个环境、17 个主题和 443 个注册资产，生成 208 张 RGB 输入。候选场景经过碰撞与稳定性检查，再由人工审查；参考几何、深度、实例掩码、对象对应关系和场景变换留在评测器内。输入只暴露图像尺寸、水平视场角、类别 taxonomy 和输出 schema，agent 无法读取评测真值。

有效性 \(V_i\) 检查 `scene.blend` 是否包含可渲染几何和活动相机，`scene.glb` 是否为非空合法导出，`final.png` 是否可解析且非退化。可见表面 Reconstruction 将提交场景与私有深度投影到图像平面，按对象掩码分组，在相机坐标中计算 F@5%；点匹配容差为参考点前向深度的 5%，并提供 F@2% 和 F@10% 诊断。Appearance 由评测器统一重渲染，在每个 RGB 通道误差不超过 30/255 的像素比例上计算。三项分数通过

\[
S_i=V_i\frac{R_i+A_i}{2},\qquad S=\frac{1}{N}\sum_i S_i
\]

聚合，失败工件保留在分母中并计零。论文附录的人类验证包含 6 名标注者、240 个样本和 960 个局部区域，整体 compatibility agreement 为 86.6%，重建为 88.9%，外观为 84.3%；在 \(|s_A-s_B|<0.05\) 视作 Both OK 的规则下，人类与指标兼容度为 83.7%。

## 主表与复杂度分析

GPT-6-astra + Codex 的室内 Validity、Reconstruction、Appearance、Overall 为 100.0、52.4、54.4、53.4；室外对应为 98.0、34.0、45.5、39.6。GPT-6-sol 室内 Overall 为 32.3，GPT-6-luna 为 23.2，GPT-5.6-sol 为 14.8。Gen3DSR 室内 Reconstruction 达 65.4%，高于 GPT-6-astra 的 52.4%，同时没有可评价的外观输出；这说明几何单项领先不能替代有效场景的整体评价。

场景复杂度从 Easy 到 Hard 时，GPT-6 与 GPT-5.6 配置的平均 Overall 从 24.6% 降到 21.3% 和 20.5%，Validity 在各层保持约 99.5%。室外 Reconstruction 的下降最明显，从 18.4% 到 12.7%。固定 42 个 Office 案例的测试时推理实验中，GPT-6-astra 从 Low 到 XHigh 由 32.3% 升至 61.8%，GPT-6-sol 由 21.3% 升至 39.7%，GPT-6-luna 由 14.4% 升至 21.2%；GPT-5.6 系列呈现弱或非单调变化。

## LEGO-Plugin 的机制证据

作者对每个可渲染中间工件重新计算 LEGO-Bench 指标，记录首个可评价场景时间、分数下降编辑比例和最佳中间结果到最终提交的差值。GPT-5.6-sol 有 29.6% 的编辑造成分数下降，最终结果比最佳中间场景低 3.2 分。LEGO-Plugin 的 Enhanced Initialization 负责建立可用起点，Grounded Refinement 将修改依据绑定到参考图像，Version Control 将每次候选更新作为可恢复版本。Office 子集上六个模型均提升，最高相对增益为 62.7%；增益属于指定子集和 harness 条件下的结果。

LEGO-World 直接查询重建场景导出 detection、instance mask 和 relative depth，省去下游任务特定训练。结果在三项任务均有有效信号，性能落后于专用视觉模型；这表明当前程序场景具备结构化查询价值，几何、相机和外观精度仍决定下游上限。附录还显示 GPT-6-astra 的 cost–performance frontier 最优质量点伴随更高 token 成本，最终状态可能低于轨迹中的最佳中间状态。

## 可迁移设计点

- 可执行场景将重建结果转化为后续可编辑、可检查、可查询的结构化对象。
- 保存并评价每个中间版本，可直接量化迭代是否持续改善，适用于其他工具调用型 agent。
- 用输入证据替代无约束自评、保留最好版本，是降低视觉编程回归风险的通用工作流思路。
