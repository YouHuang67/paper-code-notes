### WanPE：面向现代文生视频的电影化提示词增强

**WanPE: Towards Cinematic Prompt Enhancement for Modern Text-to-Video Generation** · [arXiv:2609.30221](https://arxiv.org/abs/2609.30221) · [已有深度阅读](../paper_reading/wanpe.md) · [项目页](https://wan-pe.github.io/)

**标签**：`VLM调PE` `大公司参与` `方向内通用` `多数据集或多任务`

**机构判断**：Wan Team、Alibaba Group，联合南京大学、中国科学技术大学、复旦大学和清华大学。这里的“大公司参与”指论文首页/正文明确列出的公司团队，不是引用阿里模型或仅有项目致谢。

**为什么值得从日报刷出来**：普通 prompt enhancer 往往只是在原句上补形容词；WanPE 把任务改成“为视频生成器规划一段可执行的短片”。这使它连接了用户意图、视频生成器训练分布和长时程镜头一致性，是视频生成领域内相对通用的条件建模问题。

**核心问题**：设用户请求为 $x$，增强器生成条件为 $y$，视频生成器为 $G_\phi$。增强结果既要保持用户语义，又要落在视频生成器熟悉、能执行的条件分布中。论文将目标写成：

$$
p^*(y\mid x)=\frac{p_{vg}(y)\,\mathbf{1}[y\in Y_{sem}(x)]}{Z(x)}.
$$

其中 $p_{vg}(y)$ 是从真实视频得到的 video-grounded caption 分布，$Y_{sem}(x)$ 是不遗漏、不改写、不矛盾地满足用户请求的条件集合，$Z(x)$ 是归一化项。这个公式表达了论文的核心取舍：不能只追求“描述更丰富”，还要同时满足语义保真和下游生成可执行性。

**方法动机**：视频生成器训练数据里的 caption 通常已经对应真实拍摄或剪辑完成的视频，因此天然包含镜头顺序、动作推进、光照、声音和转场等结构。直接做 forward rewriting 只会围绕用户原句继续扩写，未必学到这些真实视频中的组织方式。WanPE 采用 video-grounded reverse SFT，从视频描述反向构造用户请求，再学习从请求恢复电影化条件。

**训练流程**：

1. 从视频片段生成层级化目标，包括视频级设定、shot 时间戳、主体动作、景别、镜头运动、光照、对白、音乐、音效和转场。
2. 用 reverse SFT 学习“简单请求 → 可执行电影化条件”。论文数据约 105 万个视频片段，覆盖十类内容。
3. 对同一请求采样多份增强结果，用 Semantic-Consistency GRPO（SC-GRPO）检查风格、主体、动作、对白、声音、镜头、光照、空间关系和场景等维度，惩罚遗漏、冲突和事件顺序错误。

**实验怎么看**：WanPEval 包含 249 个请求、七类内容、5/10/15/30 秒时长、16:9 和 9:16 比例，以及 intent、scene、shot 三种粒度；60 位相关专家进行约 1.1 万次匿名两两比较。WanPE-397B 在 Wan3.0 上相对原始请求显著提升人类偏好，5–15 秒子集总体 preference score 为 50.61，30 秒子集为 60.24；论文还在 LTX-2.5-Base 和 MiniMax-H3-Base 上做格式适配，观察跨生成器迁移。

**通用性与边界**：

- **不是完全通用的 LLM 方法**：训练和评测都围绕文生视频条件生成。
- **也不是单一小垂类**：数据覆盖多种视频内容和多个时长/画幅/请求粒度，目标是视频生成前的通用 prompt planning。
- **主要限制**：模型权重、配置和推理 API 尚未完整公开；公开网页更接近论文展示和预渲染 demo，而不是可直接调用的服务。

**日报判断**：`公司参与明确`、`视频方向内通用`、`实验覆盖较广`、`值得从日报进入深读`。
